Integra seguridad y control ambiental

Coordina presencia, alarma, puerta y ventilación.

¿Qué aprenderás?

  • Asignar pines sin conflictos.
  • Separar seguridad y ventilación en el programa.
  • Probar combinaciones de entradas.

Un programa, dos responsabilidades

El subsistema de seguridad usa el PIR para decidir LEDs, alarma y posición de puerta. El subsistema ambiental usa TMP36 para decidir PWM del motor. No debe quedar la lectura de temperatura dentro de una rama que solo se ejecute con movimiento.

Conexiones coherentes

El código y la tabla de pines deben coincidir. El motor utiliza D5 para PWM y el servo D9 para señal. Utiliza una etapa de potencia para el motor, alimentación adecuada para el servo y tierras comunes.

Pruebas combinadas

Cambia una entrada a la vez y luego combina movimiento con temperatura alta. Un resultado correcto con un solo sensor no demuestra que la integración esté bien. Documenta entrada, resultado esperado y resultado observado.

Prácticas

Seguridad y ambiente

  1. Comprueba por separado el PIR, la puerta y el control térmico.
  2. Integra los módulos con la asignación del ejemplo.
  3. Ejecuta las cuatro combinaciones de movimiento/no movimiento y frío/calor.

Resultado esperado: La alarma y la puerta responden al PIR mientras el motor responde a la temperatura.

Ten en cuenta: La puerta de este proyecto representa una respuesta didáctica. Una alarma de seguridad real requiere definir por qué abrir o cerrar sería la acción apropiada.

Código Arduino

#include <Servo.h>
Servo puerta;
const int pinPIR = 2;
const int ledVerde = 3;
const int ledRojo = 4;
const int pinMotor = 5;
const int pinBuzzer = 7;
const int pinServo = 9;
const int pinTMP36 = A0;
int movimiento = LOW;
int lecturaTemperatura = 0;
int pwmMotor = 0;
float voltaje = 0.0;
float temperatura = 0.0;
void setup() {
  pinMode(pinPIR, INPUT);
  pinMode(ledVerde, OUTPUT);
  pinMode(ledRojo, OUTPUT);
  pinMode(pinMotor, OUTPUT);
  pinMode(pinBuzzer, OUTPUT);
  puerta.attach(pinServo);
  puerta.write(0);
  Serial.begin(9600);
}
void loop() {
  // ENTRADAS
  movimiento = digitalRead(pinPIR);
  lecturaTemperatura = analogRead(pinTMP36);
  voltaje = lecturaTemperatura * (5.0 / 1023.0);
  temperatura = (voltaje - 0.5) * 100.0;
  // SUBSISTEMA DE SEGURIDAD
  if (movimiento == HIGH) {
    digitalWrite(ledVerde, LOW);
    digitalWrite(ledRojo, HIGH);
    tone(pinBuzzer, 1000);
    puerta.write(90);
  } else {
    digitalWrite(ledVerde, HIGH);
    digitalWrite(ledRojo, LOW);
    noTone(pinBuzzer);
    puerta.write(0);
  }
  // SUBSISTEMA AMBIENTAL
  if (temperatura < 25.0) {
    pwmMotor = 0;
  } else if (temperatura <= 30.0) {
    pwmMotor = 150;
  } else {
    pwmMotor = 255;
  }
  analogWrite(pinMotor, pwmMotor);
  // INFORMACIÓN PARA LAS PRUEBAS
  Serial.print("PIR: ");
  Serial.print(movimiento);
  Serial.print(" | Temperatura: ");
  Serial.print(temperatura, 1);
  Serial.print(" °C | PWM motor: ");
  Serial.println(pwmMotor);
  delay(500);
}

Preguntas de repaso

1. ¿Qué lectura regula el motor en este proyecto?

  1. La del TMP36
  2. La del PIR
  3. El número de LEDs

2. ¿Por qué motor PWM en D5 y servo en D9?

  1. Para conservar una salida PWM independiente del temporizador de Servo
  2. Porque D5 mide mejor temperatura
  3. Porque los números suman 14

3. ¿Qué prueba verifica mejor la integración?

  1. Solo encender un LED
  2. Combinar las condiciones de ambos sensores
  3. Cambiar el título

Respuestas explicadas

1. La del TMP36. El subsistema ambiental calcula temperatura y selecciona el PWM.

2. Para conservar una salida PWM independiente del temporizador de Servo. En UNO R3, Servo afecta el PWM de D9 y D10; D5 sirve para este motor.

3. Combinar las condiciones de ambos sensores. Las combinaciones revelan interferencias entre los subsistemas.
