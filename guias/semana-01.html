Sistemas inteligentes con Arduino

Seguridad, iluminación y riego: tres formas de responder al entorno.

¿Qué aprenderás?

  • Distinguir entradas, decisiones y salidas.
  • Relacionar los sensores con una necesidad cotidiana.
  • Comprobar cada subsistema con diferentes valores.

Del sensor a la respuesta

Un sistema automatizado recibe información, la interpreta mediante un programa y activa una respuesta. El PIR detecta cambios de radiación infrarroja asociados al movimiento; el TMP36 entrega una señal relacionada con la temperatura; una LDR cambia su resistencia según la luz. Arduino conecta esas entradas con los actuadores.

Una decisión se puede programar

Una condición como temperatura >= 30 compara una medición con un umbral. El programa debe definir qué sucede cuando la condición se cumple y cuando no. Antes de simular, escribe una tabla con las entradas y las salidas que esperas observar.

Combinar sin confundir

Prueba la detección de movimiento y el monitoreo térmico por separado. Al integrarlos, usa nombres de variables claros y evita asignar dos funciones al mismo pin. Para alternar colores sin detener la lectura del PIR, el ejemplo utiliza millis().

Prácticas

Seguridad y monitoreo ambiental

  1. Conecta PIR, TMP36, dos LEDs, RGB de cátodo común y buzzer según la tabla del ejemplo.
  2. Prueba movimiento y ausencia de movimiento; después cambia la temperatura alrededor de 30 °C.
  3. Observa que el RGB alterna rojo/naranja o verde/azul mientras la alarma sigue respondiendo.

Resultado esperado: El PIR controla la alarma y el TMP36 selecciona la secuencia de colores.

Iluminación y riego automático

  1. Dibuja las entradas y salidas de una lámpara que solo se encienda con oscuridad y presencia.
  2. Representa la humedad del suelo mediante una entrada analógica y define cuándo debe solicitarse riego.
  3. Usa un LED para representar la bomba durante el diseño; registra al menos cuatro escenarios.

Resultado esperado: Puedes justificar cada decisión con una condición, sin conectar una bomba directamente a Arduino.

Código Arduino

// Aula Arduino - seguridad y monitoreo ambiental
// RGB de catodo comun. Resistencias independientes por canal.
const int pinPIR = 4, pinTMP36 = A0;
const int ledVerde = 2, ledRojo = 7, buzzer = 8;
const int rgbRojo = 5, rgbVerde = 6, rgbAzul = 9;
unsigned long ultimoCambio = 0;
bool fase = false;

void setup() {
  pinMode(pinPIR, INPUT);
  pinMode(ledVerde, OUTPUT); pinMode(ledRojo, OUTPUT);
  pinMode(buzzer, OUTPUT);
  pinMode(rgbRojo, OUTPUT); pinMode(rgbVerde, OUTPUT);
  pinMode(rgbAzul, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  bool movimiento = digitalRead(pinPIR) == HIGH;
  digitalWrite(ledRojo, movimiento ? HIGH : LOW);
  digitalWrite(ledVerde, movimiento ? LOW : HIGH);
  if (movimiento) tone(buzzer, 1000);
  else noTone(buzzer);

  float voltaje = analogRead(pinTMP36) * (5.0 / 1023.0);
  float temperatura = (voltaje - 0.5) * 100.0;

  // Alternar sin bloquear las lecturas del PIR.
  unsigned long ahora = millis();
  if (ahora - ultimoCambio >= 500) {
    ultimoCambio = ahora;
    fase = !fase;
    Serial.print("Temperatura: ");
    Serial.println(temperatura, 1);
  }
  if (temperatura >= 30.0) {
    analogWrite(rgbRojo, 255);
    analogWrite(rgbVerde, fase ? 100 : 0);
    analogWrite(rgbAzul, 0);
  } else {
    analogWrite(rgbRojo, 0);
    analogWrite(rgbVerde, fase ? 255 : 0);
    analogWrite(rgbAzul, fase ? 0 : 255);
  }
}

Preguntas de repaso

1. ¿Qué elemento recibe información del entorno?

  1. El sensor
  2. El actuador
  3. El cable USB

2. ¿Qué condición representa una temperatura alta desde 30 °C?

  1. temperatura > 30
  2. temperatura >= 30
  3. temperatura < 30

3. ¿Por qué probar por separado cada subsistema?

  1. Para evitar usar variables
  2. Para identificar con más facilidad dónde ocurre una falla
  3. Para prescindir del programa

Respuestas explicadas

1. El sensor. El sensor convierte una condición física en una señal que el controlador puede interpretar.

2. temperatura >= 30. >= incluye exactamente 30 °C y los valores superiores.

3. Para identificar con más facilidad dónde ocurre una falla. Una prueba por módulos permite localizar errores antes de integrar todo el circuito.
